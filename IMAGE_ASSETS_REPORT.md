## Notes & Recommendations

- This project uses source references like `/assets/file.png` and `./assets/file.png`, which in this Vite setup means the files should live in `public/assets/` so they are served as static public assets.
- The safest convention for React components here is to use `/assets/...` instead of `./assets/...`. The current `Navbar` and `Footer` logo paths work under the current hash-router setup, but absolute public paths are less fragile if deployment base paths change.
- Most page screenshots are currently missing from `public/assets/`. The referenced files present now are `logo_icon.png`, `logo_splash_light.png`, `main-dashboard.png`, `main-orders.png`, `main-preparation.png`, `main-reports.png`, and `main-mobile.png`. All other referenced screenshots in the table above need to be added or they will render as broken images.
- For the page hero screenshots, the code renders at `780 x 480`, so exporting at 2x (`1560 x 960`) is a good balance of sharpness and file size.
- For walkthrough screenshots, the code renders at `880 x 540`, so exporting at 2x (`1760 x 1080`) is the right target.
- For the `SystemPreview` carousel, use clean 16:9 screenshots. `1920 x 1080` is ideal if you want crisp results on larger displays.
- Prefer WebP for photographic or screenshot-heavy assets when possible, but only after updating the source references to match the new extension. Right now the code explicitly expects `.png` filenames.
- If you want optimization without touching code, keep the listed filenames and export compressed PNGs. If you want better performance, rename the references to `.webp` and regenerate the assets in WebP.
- The app also uses many inline icons from `lucide-react`. Those do not require any image files and are therefore intentionally not listed in the table.
- `public/assets/dashboard_mockup.png` exists in the repo but is not currently referenced anywhere in source code, so it was excluded from the asset inventory.
